# Tangison Brand & Photo Studio

Inputs: client name, one logo file (any format/quality), a set of raw premises/product photos, brand context (industry, target audience, town). If the client has no clear brand colors yet, derive them from the logo — never invent colors that aren't in the source art.

1. Logo intake and cleanup. Identify if the source is a clean vector-able graphic or a lossy photo/screenshot (JPEG artifacts, uneven background). For lossy sources: remove background with a flood-fill from the image edges only (never a flat white-distance threshold — it will eat white shapes drawn *inside* the logo, like a shirt or a bed). Snap colors to a small fixed palette sampled from the dominant pixels to kill compression noise, then trace to SVG. Verify by compositing over a checkerboard and over a magenta canvas before calling it done — a plain white-background preview will hide a transparency bug.
2. Brand asset pack. From the cleaned logo produce: full logo (light bg, transparent, dark/reversed for dark backgrounds), icon-only crop, sizes from favicon (32px) up to print (2000px+), and a one-page palette sheet with exact hex/RGB pulled from the source art (never estimated). Package as a single zip, organized by Logo-Light / Logo-Dark / Icon-Only / Brand-Palette.
3. Raw photo intake. Group the client's raw photos by room/subject type (commonly 3 per group: e.g. common areas, kitchen+bathroom, hero exteriors, detail exteriors). Build one labeled contact-sheet image per group: numbered badges on each photo, a black caption bar naming the room, and a bottom reference strip carrying the *correct, current* brand logo plus its exact hex swatches. Confirm with the client which logo file is current before building this — if more than one logo has been discussed in the conversation, ask or re-check rather than assuming.
4. Restyle prompts, one per gallery, JSON only. Every prompt object follows the same schema so they're a "pattern," not one-offs:
   - `output`: single combined image, same layout as the source sheet — tell the agent explicitly not to return separate images (saves generation calls).
   - `brand_assets.logo_usage`: use the provided logo file exactly as given, never redraw/recreate/reinterpret it; crop and place the source file pixel-for-pixel if it needs to appear in a panel (e.g. a wall sign).
   - `global_style`: editorial, photorealistic, natural light; explicit avoid-list (illustration look, warped hands/faces, extra limbs, stock-photo posing, AI-plastic skin).
   - `panels`: per-photo edit instructions, whether people are added, and their description — when the client wants local representation, describe it plainly and respectfully (skin tone range, hairstyles, region) and explicitly exclude any group the client doesn't want, rather than defaulting to a generic stock look.
   - `copy_pattern`: optional headline/subtext/cta block, only when the images are for a channel that uses on-image text (flyers, social posts) — never bake captions or contact details into images meant for a website, since site copy and domains change independently of the photos.
   - `negative_instructions`: restate the two things that go wrong most — logo reinvention, and people appearing where the room should stay empty.
5. Post-batch cropping. When the client returns AI-restyled contact sheets, crop each panel back out into individual files. Don't eyeball it: detect the white/black gaps between panels programmatically (column and row pixel scans for uniform bands), because label-bar presence and exact panel size can vary between batches from the same tool. Spot-check a few crops before delivering the full set — check hands, faces, and any rendered sign text for garbling before calling a batch done.
6. Channel placement guidance. Map the final images to where they'll actually go: one hero shot, a small set for social (with captions, sized per-platform), a gallery/amenities set (no single hero needed), and — if the client wants website hero assets specifically — a separate cutout batch on pure white background, logo icon attached only as a color reference for the agent, not stamped onto the images.

Output: the brand asset zip, the labeled contact sheets, the JSON restyle prompts (as text, not as saved artifacts, unless the client asks to keep them), the cropped individual finals, and a short plain-language placement guide.

Rules: never fabricate a color, dimension, or file detail that wasn't measured from the source art — sample it. If the client has shown more than one candidate logo in the conversation, confirm which is current before reusing it in any new asset; a wrong-logo mistake is worse than asking. Keep photos meant for a live website free of baked-in text, phone numbers, or domains, since those change independently. Any added people in restyled photos must match what the client asked for, described in plain descriptive terms, never a named real person. Flag to the client, plainly, that Claude does not have a photorealistic image-generation tool in this environment — the deliverable is the JSON prompt for their AI image tool of choice, not a rendered final unless the client supplies the rendered result back for cropping/QA. Namibian context (N$, +264) in any copy_pattern text. No em dashes.
